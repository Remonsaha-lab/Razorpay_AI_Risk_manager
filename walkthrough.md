```text
# Node / Frontend

.next/

.vercel

# IDE
.vscode/
```

**What each section does:**
- **Python section:** Ignores compiled bytecode (`__pycache__`) and the virtual environment (`.venv/`) — these are machine-specific and regenerated
- **`.env`:** Your API keys for OpenAI/Gemini will go here. NEVER committed. The `.env.example` (next step) shows what variables are needed without the actual values
- **Node section:** `node_modules/` can be 500MB+ and is regenerated by `npm install`. `.next/` is build output
- **IDE section:** Your VS Code settings are personal, not project code

## Step 5: Create the Folder Structure

**Why:** The implementation guide prescribes a specific layout where each folder has one clear job. This separation is critical:
- `backend/api/` handles HTTP only — never makes decisions
- `backend/domain/` defines data shapes — the "nouns" of the system
- `backend/validators/` does deterministic checks — the safety layer
- `backend/workflow/` orchestrates the pipeline — the "verbs"
- `backend/services/` wraps external tools (OCR, LLM, PDF) — isolatable and testable
- `backend/policies/` stores rules as config, not code — swappable without code changes

Run these commands to create all folders with placeholder `__init__.py` files (Python needs these to treat folders as importable packages):

```powershell

mkdir backend\workflow
mkdir backend\services
mkdir backend\validators
mkdir backend\policies

# Data folders
mkdir data\fixtures
mkdir data\held_out

# Other folders
mkdir evals
mkdir tests
mkdir docs
```

Now create empty `__init__.py` files so Python recognizes these as packages:


## Step 6: Backend Scaffold — Python Virtual Environment

**Why:** A virtual environment (`.venv`) is an isolated Python installation for THIS project only. Without it, pip installs go into your system Python and conflict with other projects. The buildathon guide explicitly requires this.

### 6a. Create and activate the virtual environment

```powershell
python -m venv .venv
```
> This creates a `.venv/` folder with a clean Python copy. Takes ~10 seconds.

```powershell
.\.venv\Scripts\Activate.ps1
```
> Your prompt should now show `(.venv)` at the start. This means all `pip install` and `python` commands use the isolated environment.

> [!WARNING]
> If you get a "running scripts is disabled" error, run this first (one-time, current terminal only):
> ```powershell
> Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
> ```
> Then try the activate command again.

### 6b. Install core dependencies

```powershell
python -m pip install --upgrade pip
```
> Always upgrade pip first — old versions can fail on newer packages.

```powershell
pip install fastapi "uvicorn[standard]" pydantic pytest httpx
```

**What each package does:**
| Package | Purpose |
|---|---|
| `fastapi` | The web framework for your API. Gives you automatic docs, validation, and typed endpoints |
| `uvicorn[standard]` | The server that runs FastAPI. The `[standard]` extra adds faster performance features |
| `pydantic` | Data validation using Python type hints. Your domain models (Dispute, Evidence, etc.) will be Pydantic models |
| `pytest` | Test runner. You'll write tests for validators and the decision engine |
| `httpx` | HTTP client for testing your API endpoints programmatically |

### 6c. Freeze dependencies

```powershell
pip freeze > backend\requirements.txt
```
> This saves the exact versions installed (e.g., `fastapi==0.115.0`). Anyone cloning your repo can run `pip install -r backend/requirements.txt` to get the exact same versions. Reproducibility matters for the buildathon.

✅ **After this step, you should have `(.venv)` in your prompt and a `backend/requirements.txt` file.**

## Step 7: Create the FastAPI Application

**Why:** This is the beating heart of your backend. FastAPI gives you:
- Automatic input validation (via Pydantic)
- Auto-generated API documentation at `/docs`
- Type safety throughout

You need to create **two files**. I'll explain each:

### 7a. Create `backend/main.py`

This is the application entry point — the file uvicorn loads to start your server.

Create `backend/main.py` with this content:

```python
"""DisputeGuard — FastAPI application entry point."""

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from backend.api.routes import router

app = FastAPI(
    title="DisputeGuard API",
    description="Evidence-grounded AI for chargeback decisioning and representment.",
    version="0.1.0",
)

# Allow the Next.js frontend (port 3000) to call this API (port 8000)
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

app.include_router(router)
```

**Line-by-line explanation:**
- **`FastAPI(...)`** — Creates the app with metadata that shows up in the auto-docs
- **`CORSMiddleware`** — Browsers block requests between different ports by default (security). This tells the backend "requests from localhost:3000 are allowed." Without this, your frontend can't talk to the backend
- **`app.include_router(router)`** — Imports all API endpoints from a separate routes file (separation of concerns)

### 7b. Create `backend/api/routes.py`

This file defines your API endpoints. Start with a health check and a sample fixture endpoint.

Create `backend/api/routes.py`:

```python
"""API routes — HTTP input/output only, never core decisions."""

from fastapi import APIRouter

router = APIRouter()


@router.get("/health")
async def health_check():
    """Verify the API is running."""
    return {"status": "healthy", "service": "DisputeGuard"}


@router.get("/cases")
async def list_cases():
    """Return available synthetic dispute cases."""
    # Placeholder — will load from data/fixtures/ in Step 5
    return {
        "cases": [
            {
                "id": "DSP-2026-001",
                "amount_inr": 18400,
                "reason": "Merchandise/services not received",
                "status": "pending_review",
            }
        ]
    }


@router.get("/cases/{case_id}")
async def get_case(case_id: str):
    """Return a single dispute case by ID."""
    # Placeholder — will load full case from fixtures
    if case_id == "DSP-2026-001":
        return {
            "id": "DSP-2026-001",
            "amount_inr": 18400,
            "reason": "Merchandise/services not received",
            "respond_by": "2026-09-04T18:00:00+05:30",
            "status": "pending_review",
        }
    return {"error": f"Case {case_id} not found"}
```

**Why this structure:**
- `APIRouter()` groups related endpoints. As you add more (like `/cases/{id}/run`, `/cases/{id}/packet`), they all go here
- The routes return placeholder data for now — just enough to prove the server works
- Notice: **no business logic here**. The API layer's job is HTTP in/out only. Decisions will live in `backend/workflow/`

### 7c. Launch and verify the backend

**What this command means:**
- `backend.main:app` — "In the `backend` package, find `main.py`, and use the `app` object"
- `--reload` — Auto-restart when you save file changes (dev mode only)
- `--port 8000` — Listen on port 8000
